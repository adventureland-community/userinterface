Instance / Event module mockups

Static HTML explorations grounded in game/server data and /comm today. See full analysis (generic vs specific, observer constraints, implementation order).

comm live in enhance-comm-ui extend same APIs, not wired yet meter combat meters only G+S design + server_info player needs a player socket — not on client today

Live mockups: interactive pages include mock-live.js (shared tick + bindings) and feature modules such as mock-ability-timeline.js — ticking event countdowns, spawn alerts (only when imminent/firing), ability CDs, HP, and scores. Spawn chips are not static labels; they flash when relevant.

Styles: pages link shared.css, which aggregates shared-core.css, shared-timeline.css, shared-mechanics.css, and shared-viz.css.

Panel layout: mockups use a mock-stage with separate PositionedPanel-style units (chrome bar + panel id). Each box can be moved independently in comm layout mode. See full layout demo.

Observer lens: /comm runs on the observer client. You watch via camera + entity snapshots; you do not have a players[socket] record. Event join/signup, movement, combat, and inventory actions belong to the observed player (or their game client), not the observer HUD.

Observer can vs cannot
