Client vs comm viz

Bottom line: Comm should add observer-specific affordances the client does not provide (multi-boss HUD, forward CD timeline, imminent ability rings) by composing existing data (entities, G.monsters, entity.s). It should not reimplement border_mode, native HP bars, or always-on map clutter. Map viz belongs in comm only where CODE proves the API works and the feature is toggleable — which is exactly what the visualization lab mockups sketch.

When to draw (CD gating)

Server stores countdown in entity.s[abilityKey].ms (ticks down, fires at 0, resets to full cooldown). For HUD clutter control:

  • Imminent — ms / cooldown < 0.15 (or < 2s): solid ring + player highlights
  • Just fired — brief flash (200–400ms) then hide until next imminent window
  • Mid CD — hide ring (default) or ghost ring (user setting, like test script always-on)
  • Abilities without radius — no world ring (spawn timers, self_heal, etc.)

Player “would hit” highlighting

Use stock distance(a,b) (rectangle edge distance, not center-to-center — matches server). Filter like server where possible: skip rip; note observer may not know invis.

Ability typeServer behaviorHighlight
zap, aurasAll players in radiusHighlight all inside ring
anger, warpstomp, deepfreezerandom_one in radiusHighlight all in radius as at risk (not predicted target)
Attack rangeentity.rangeRed circle always on focused boss (test script default)

Visual language (extend test_visualize_skills)

  • Stable color per ability key (generateColorFromKey hash → HSL)
  • Imminent: solid stroke, light fill, pulse alpha
  • On CD ghost: dashed stroke, low alpha (anger r300 vs warp r100 use different dash)
  • Label: ability name at ring edge (optional, toggle)
  • Player tint: reuse comm add_tint / sprite filter or draw small ring under feet

Comm implementation sketch

abilityOverlay.ts
  tick (250ms, match test script)
  target ← bossBar focus || instance aggro boss
  for ability in G.monsters[target.mtype].abilities:
    if !ability.radius → continue
    phase ← cdPhase(target.s[ability].ms, ability.cooldown)
    if phase === hidden → continue
    drawCircle(gfx, target, ability.radius, color, style[phase])
    if phase === imminent && settings.highlightPlayers:
      for player in visiblePlayers:
        if distance(target, player) < ability.radius → markAtRisk(player)

Cleanup: single PIXI.Graphics child on map, destroyed/redrawn each tick (same as test script). Guard with game.graphics / no_graphics mode.

Alternative: ship as observer COMMAND preset (remote CODE snippet) for users who want it now without comm bundle changes — comm first-party module is cleaner for settings + bossBar integration.

Debug entity lines (PIXI / map overlay)

Visualization lab — toggle matrix under Debug · entity lines. Draws draw_line-style segments from each entity’s real_x/y (mock uses SVG coords). Same ~4 Hz redraw as ability rings.

Line types

Setting keyFrom → toGame fieldsDefault kind
lines.moveDest Entity position → movement goal real_x/y → going_x/y Monsters + players (when moving)
lines.aggroTarget Monster → aggro target entity.target (player id) Monsters only
lines.attackTarget Entity → combat target entity.target (mob or player id) Players (party bots / manual focus)

Filters

  • lines.filter.monsters / lines.filter.players — entity kind gate
  • lines.filter.focusOnly — only draw for bossBar / instance focus mob

Per-mtype overrides

Stored separately in localStorage key ecu-viz-line-mtypes. Each row is an mtype or explicit entity id (e.g. gpurplepro, zapper0, p:Alice). Values override kind defaults: 

{
  "gpurplepro": { "moveDest": false, "aggroTarget": true, "attackTarget": false },
  "zapper0":    { "moveDest": true,  "aggroTarget": false },
  "p:Bob":      { "attackTarget": true }
}

Resolution order: global toggle → kind filter → focus filter → per-mtype rule (merged with kind preset). Production comm UI: same grid in settings, keyed by G.monsters[mtype].name.

Comm implementation sketch

entityLineOverlay.ts
  tick (250ms)
  gfx.clear()
  for entity in visibleEntities(map):
    if !passesFilter(entity, settings) → continue
    rules ← mtypeRules[entity.mtype] ?? kindDefaults[entity.type]
    if rules.moveDest && moving(entity):
      draw_line(entity.real_x, entity.real_y, entity.going_x, entity.going_y, 1, COLOR_MOVE)
    if entity.target && rules.aggroTarget && entity.type === "monster":
      t ← entities[entity.target]; draw_line(entity, t, COLOR_AGGRO)
    if entity.target && rules.attackTarget:
      t ← entities[entity.target]; draw_line(entity, t, COLOR_TARGET)

Replaces the single static aggro segment (world.targetLine legacy mock). Observer CODE presets already draw move lines for the local character — comm module generalizes to all filtered entities with persistent settings.

Simulation limits

  • Spawn randomizes initial s[a].ms — cannot know absolute phase until first observed packet
  • CD ticks pause when monster is_disabled — not exposed on wire
  • entities updates are sparse (not every server tick) — bars jitter unless interpolated
  • Off-vision boss = no CD state (vision-gated xy_emit)

Server wishlist (accurate boss-mod grade)

  • ability_used — { id, ability, targetId?, nextReadyAt } on every fire
  • Include monster.a overrides on entity sync (per-instance damage/radius)
  • Optional party combat relay for off-screen boss CD (observer use case)

Recommended implementation order

  1. Split topCenter — separate serverInfo and mapInfo panel ids so clock chips and instance id move independently
  2. Generalize instance tracker — rename crypt → instance; add instanceRun for progress/phase/luckm; config table from maps.js mtypes
  3. Extend ServerInfo → events panel — new closable events panel; fix end/spawn countdown; read-only for observer
  4. AB Testing panels — eventScore + eventRoster (data already in S.abtesting + entities)
  5. Per-map layout variants — tomb compass, winter phase list, spider 3+adds (content inside instance, not new panel ids)

Observer constraints (all modules)

  • No join / signup — display state only
  • Instance keys (cryptkey, etc.) consumed on entry — do not show inside dungeon HUD
  • Bag/gear from live getObserving().slots; bag snapshot stale until reconnect
  • Follow player to event maps — camera does not self-join
